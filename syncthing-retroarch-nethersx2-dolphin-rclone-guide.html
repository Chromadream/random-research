1. Overview & Architecture

This guide sets up a hub-and-spoke synchronization architecture. Your Linux desktop acts as the central hub — it runs Syncthing 24/7, collecting saves from all your Android handhelds. Whenever you finish playing on one device, its saves sync to the Linux hub. When you pick up another device, the latest saves are waiting for you. On top of that, rclone periodically backs up the entire synced folder to Google Drive for off-site redundancy.

┌──────────────────────────────────────────────────────┐ │ ARCHITECTURE OVERVIEW │ ├──────────────────────────────────────────────────────┤ │ │ │ Android Handheld #1 Android Handheld #2 │ │ ┌──────────────┐ ┌──────────────┐ │ │ │ RetroArch │ │ RetroArch │ │ │ │ NetherSX2 │ │ NetherSX2 │ │ │ │ Dolphin │ │ Dolphin │ │ │ └──────┬───────┘ └──────┬───────┘ │ │ │ Syncthing-Fork │ │ │ │ │ │ │ └──────────┬────────────────┘ │ │ ▼ │ │ ┌──────────────────┐ │ │ │ LINUX DESKTOP │ │ │ │ (Syncthing Hub) │ │ │ │ ~/Sync/Emulators/│ │ │ └────────┬─────────┘ │ │ │ rclone copy │ │ ▼ │ │ ┌──────────────────┐ │ │ │ GOOGLE DRIVE │ │ │ │ (Cloud Backup) │ │ │ └──────────────────┘ │ └──────────────────────────────────────────────────────┘
Key concepts: Syncthing is peer-to-peer — there is no cloud middleman. Your data stays private and encrypted (TLS). Devices must be online simultaneously to sync. The Linux hub keeps all saves centralized, and rclone handles the off-site backup to Google Drive.

2. Emulator Save File Locations on Android

Knowing exactly where each emulator stores its files is critical. Here are the paths for Android devices:

RetroArch

Data TypePathAccessible?
In-game saves (.srm) /storage/emulated/0/RetroArch/saves/<core_name>/ ✅ Yes — fully accessible
Save states (.state) /storage/emulated/0/RetroArch/states/<core_name>/ ✅ Yes — fully accessible
Cheats /storage/emulated/0/RetroArch/cheats/ ✅ Yes
Config /storage/emulated/0/RetroArch/config/ ✅ Yes
In RetroArch, go to Settings → Saving and ensure:
✅ Sort Saves into Folders by Core Name = ON
✅ Sort Save States into Folders by Core Name = ON
✅ Write Saves to Content Directory = OFF
✅ Write Save States to Content Directory = OFF

This ensures saves go into the standard RetroArch folder structure, not alongside your ROMs.

NetherSX2 / AetherSX2

Data TypePathAccessible?
Memory cards /storage/emulated/0/Android/data/xyz.aethersx2.android/files/memcards/ ⚠️ Behind scoped storage
Save states /storage/emulated/0/Android/data/xyz.aethersx2.android/files/sstates/ ⚠️ Behind scoped storage
Cheats /storage/emulated/0/Android/data/xyz.aethersx2.android/files/cheats/ ⚠️ Behind scoped storage
Game settings /storage/emulated/0/Android/data/xyz.aethersx2.android/files/gamesettings/ ⚠️ Behind scoped storage
Textures /storage/emulated/0/Android/data/xyz.aethersx2.android/files/textures/ ⚠️ Behind scoped storage
Android scoped storage problem: On Android 11+, Android/data/ is restricted. Normal file managers and even Syncthing's app UI cannot access it. However, Syncthing's Web GUI (accessed via browser at 127.0.0.1:8384) can browse into these folders on some devices (Retroid, AYN Odin). On Anbernic Android devices, even the Web GUI is blocked — you may need root or the manual workaround.

Dolphin (Official)

Data TypePathAccessible?

Wii saves /storage/emulated/0/Android/data/org.dolphinemu.dolphinemu/files/Wii/title/ ⚠️ Behind scoped storage
Save states /storage/emulated/0/Android/data/org.dolphinemu.dolphinemu/files/StateSaves/ ⚠️ Behind scoped storage
Game settings /storage/emulated/0/Android/data/org.dolphinemu.dolphinemu/files/GameSettings/ ⚠️ Behind scoped storage
Load/Textures /storage/emulated/0/Android/data/org.dolphinemu.dolphinemu/files/Load/Textures/ ⚠️ Behind scoped storage
Recent Dolphin builds (2025+) have added a DocumentProvider flag that makes Dolphin appear as a "local" file provider. This means third-party apps like Syncthing can now detect and sync Dolphin's folder. Ensure you're on a recent Dolphin dev build for this to work. In Dolphin, you can also use Settings → Config → User Data → Export User Data as a manual backup method.

Part 1: Setting Up Syncthing on Linux (Hub)

Installation

Option A — Ubuntu/Debian via official repo (recommended for latest version):

# Add the release PGP keys:
sudo mkdir -p /etc/apt/keyrings
sudo curl -L -o /etc/apt/keyrings/syncthing-archive-keyring.gpg https://syncthing.net/release-key.gpg

# Add the stable channel:
echo "deb [signed-by=/etc/apt/keyrings/syncthing-archive-keyring.gpg] https://apt.syncthing.net/ syncthing stable-v2" | sudo tee /etc/apt/sources.list.d/syncthing.list

# Update and install:
sudo apt-get update
sudo apt-get install syncthing

Option B — From default repos (may be older):

sudo apt update
sudo apt install syncthing

Option C — Fedora:

sudo dnf install syncthing

Option D — Arch:

sudo pacman -S syncthing

Enable as a User Service (Recommended)

# Enable and start Syncthing for your user:
systemctl --user enable syncthing
systemctl --user start syncthing

# Check it's running:
systemctl --user status syncthing

# Optional: enable lingering so it runs even when logged out
sudo loginctl enable-linger $USER

Access the Web GUI

Open your browser and navigate to:

http://127.0.0.1:8384
Set a GUI password! In the Web GUI, go to Actions → Settings → GUI and set a username and password. This is especially important if you allow remote access by changing the GUI listen address from 127.0.0.1:8384 to 0.0.0.0:8384 in ~/.config/syncthing/config.xml.

Configure Firewall (if using UFW)

sudo ufw allow 22000/tcp
sudo ufw allow 22000/udp
sudo ufw allow 21027/udp

Create the Hub Sync Folders

We'll create a structured folder on your Linux desktop that mirrors what each emulator needs:

~/Sync/Emulators/ ├── RetroArch/ │ ├── saves/ ← synced with Android RetroArch/saves/ │ ├── states/ ← synced with Android RetroArch/states/ │ └── cheats/ ← optional ├── NetherSX2/ │ ├── memcards/ ← synced with Android/data/.../files/memcards/ │ ├── sstates/ ← synced with Android/data/.../files/sstates/ │ └── gamesettings/ ← optional └── Dolphin/ ├── GC/ ← synced with Android/data/.../files/GC/ ├── Wii/ ← synced with Android/data/.../files/Wii/ ├── StateSaves/ ← synced with Android/data/.../files/StateSaves/ └── GameSettings/ ← optional 
mkdir -p ~/Sync/Emulators/{RetroArch/{saves,states,cheats},NetherSX2/{memcards,sstates,gamesettings},Dolphin/{GC,Wii,StateSaves,GameSettings}}

Now, in the Syncthing Web GUI, add each subfolder you want to sync as a separate folder. Use Add Folder and set the path. Enable File Versioning → Simple File Versioning (keeps 5 old versions — a lifesaver if a save corrupts).

Why separate folders per emulator and per type? This gives you fine-grained control. Maybe you only want to sync in-game saves (not save states) for Dolphin, or skip texture packs. Separate folders also avoid one emulator's file structure confusing another.

Part 2: Setting Up Syncthing on Android Handhelds

Important: The official Syncthing Android app was discontinued in late 2024. You MUST use Syncthing-Fork by Catfriend1, available on F-Droid. Do not use the old Play Store version — it is unmaintained.

Install Syncthing-Fork

  1. Install F-Droid on your Android handheld
  2. Search for "Syncthing-Fork" and install it
  3. Alternatively, download the APK directly from the GitHub releases page

Initial Android Setup

  1. Open Syncthing-Fork and grant storage permissions when prompted
  2. Turn off Battery Optimization for Syncthing-Fork (Android Settings → Apps → Syncthing → Battery → Unrestricted)
  3. IMPORTANT: Use the Web GUI for adding folders that are in Android/data/ — the app's native UI cannot browse into scoped storage directories
1 Open the Web GUI: In Syncthing-Fork, tap the menu → Web GUI. This opens http://127.0.0.1:8384 in your browser. For scoped storage folders, this is the only way to browse into Android/data/.

Battery Optimization Settings (Critical!)

In Syncthing-Fork, go to Settings → Syncthing Options and set:

  • Global discovery: OFF (if only syncing at home)
  • Enable Relaying: OFF (if only syncing at home)

Go to Settings → Run Conditions:

  • Run on mobile data: OFF
  • Run without network connection: OFF
  • Run according to time schedule: ON
  • Duration of the sync cycle: 5 minutes

This makes Syncthing run for 5 minutes every hour, dramatically reducing battery drain. When you want to force an immediate sync (e.g., after a gaming session), tap FORCE START / IGNORE RUN CONDITIONS in the Status tab.

Part 3: Syncing RetroArch Saves & States

RetroArch is the easiest to sync because its saves and states are stored in a publicly accessible location. No root required.

On Each Android Handheld

  1. Open RetroArch → Settings → Saving and confirm the settings from Section 2
  2. Go to Main Menu → Configuration File → Save Current Configuration

On the Linux Hub

  1. In Syncthing Web GUI, add a folder with path ~/Sync/Emulators/RetroArch/saves, label it ra-saves
  2. Add another folder with path ~/Sync/Emulators/RetroArch/states, label it ra-states
  3. Enable File Versioning → Simple File Versioning for both

Link Each Android Handheld

  1. On the Linux Syncthing Web GUI, click Add Remote Device
  2. Your Android device should appear in the list — click its Device ID
  3. In the Sharing tab, check ra-saves and ra-states
  4. Click Save
  5. On the Android Syncthing Web GUI, accept the device connection prompt
  6. Accept the folder share prompts. For ra-saves, set the folder path to: 
    /storage/emulated/0/RetroArch/saves
  7. For ra-states, set the folder path to: 
    /storage/emulated/0/RetroArch/states
Using Ignore Patterns: Instead of creating separate folders for saves, states, and cheats, you can add the entire RetroArch folder as one sync folder and use ignore patterns to include only what you want:
!saves
!states
!cheats
*
This tells Syncthing: "ignore everything except saves, states, and cheats."

Part 4: Syncing NetherSX2 / AetherSX2 Saves

This is the trickiest emulator to sync. NetherSX2 stores data in Android/data/xyz.aethersx2.android/files/, which is behind Android's scoped storage. Also, NetherSX2 currently does not allow changing the memory card or save state directory. The workaround depends on your device.

Scenario A: Retroid / AYN Odin Devices (Syncthing Web GUI works)

On these devices, the Syncthing Web GUI can browse into Android/data/. Simply use the Web GUI to add the folder:

  1. On your Linux hub, create a folder ~/Sync/Emulators/NetherSX2/memcards and share it
  2. On the Android device's Syncthing Web GUI (not the app UI), accept the share
  3. Set the folder path to: 
    /storage/emulated/0/Android/data/xyz.aethersx2.android/files/memcards
  4. Repeat for sstates (save states): 
    /storage/emulated/0/Android/data/xyz.aethersx2.android/files/sstates

Scenario B: Anbernic Android / Locked Devices (Root Workaround)

If the Web GUI also cannot access Android/data/, you need an indirect approach. This method uses Syncthing to sync to a different accessible folder, then a root script copies files into the protected location:

Step 1: Set up a bridge folder

# On the Android device, create a folder Syncthing CAN access
mkdir -p /storage/emulated/0/Syncthing/NetherSX2/memcards
mkdir -p /storage/emulated/0/Syncthing/NetherSX2/sstates

Step 2: Sync to the bridge folder

In Syncthing (Web GUI), accept folder shares and point them to the bridge folders above (NOT to Android/data/).

Step 3: Create a copy script (requires root via ADB)

Connect via ADB and create a sync script:

adb shell
su
cat > /data/media/0/sync_nethersx2.sh << 'EOF'
#!/bin/sh
# Copy from Syncthing bridge → protected NetherSX2 folder
cp -r /data/media/0/Syncthing/NetherSX2/memcards/. \
      /data/media/0/Android/data/xyz.aethersx2.android/files/memcards/
cp -r /data/media/0/Syncthing/NetherSX2/sstates/. \
      /data/media/0/Android/data/xyz.aethersx2.android/files/sstates/
# Fix ownership
STAT_OUT=$(stat /data/media/0/Android/data/xyz.aethersx2.android)
UID=$(echo "$STAT_OUT" | grep "Uid:" | awk '{print $2}' | cut -d'/' -f1)
chown -R $UID:ext_data_rw /data/media/0/Android/data/xyz.aethersx2.android/files/
EOF
chmod +x /data/media/0/sync_nethersx2.sh

Step 4: Also sync in reverse (device → hub)

Create a second script that copies FROM the protected folder TO the bridge folder after you finish playing:

cat > /data/media/0/sync_nethersx2_reverse.sh << 'EOF'
#!/bin/sh
cp -r /data/media/0/Android/data/xyz.aethersx2.android/files/memcards/. \
      /data/media/0/Syncthing/NetherSX2/memcards/
cp -r /data/media/0/Android/data/xyz.aethersx2.android/files/sstates/. \
      /data/media/0/Syncthing/NetherSX2/sstates/
EOF
chmod +x /data/media/0/sync_nethersx2_reverse.sh
Automate with MacroDroid: Install MacroDroid from the Play Store. Create a macro: Trigger → Application Launched → NetherSX2, Action → Shell Script (root) → /data/media/0/sync_nethersx2.sh. Create a second macro: Trigger → Application Closed → NetherSX2, with the reverse script. This automatically pulls saves before you play and pushes them when you're done.
Manual fallback: If root is not an option at all, use NetherSX2's built-in Transfer Data → Export feature periodically. Open NetherSX2, go to the left menu → Transfer Data → Export, choose a folder (like Downloads), and then use Syncthing to sync that export folder. To restore, use Transfer Data → Import. This is manual but works on any device.

Part 5: Syncing Dolphin Saves & Save States

Dolphin's data lives in Android/data/org.dolphinemu.dolphinemu/files/. Recent Dolphin builds (2025+) added a DocumentProvider with a "Local only" flag, which makes Dolphin's data visible to Syncthing on some devices.

On Your Linux Hub

Create the Dolphin sync folders:

mkdir -p ~/Sync/Emulators/Dolphin/{GC,StateSaves,GameSettings}

In Syncthing Web GUI, add each as a separate folder and share them.

On Android (Scenario A: Syncthing Can Access)

On Retroid and AYN devices, use the Syncthing Web GUI and point to:

  • GC saves: /storage/emulated/0/Android/data/org.dolphinemu.dolphinemu/files/GC
  • Save states: /storage/emulated/0/Android/data/org.dolphinemu.dolphinemu/files/StateSaves
  • Game settings: /storage/emulated/0/Android/data/org.dolphinemu.dolphinemu/files/GameSettings

On Android (Scenario B: Locked Device)

Use the same bridge-folder + root-script approach as NetherSX2, substituting the package name:

# Bridge folders:
mkdir -p /storage/emulated/0/Syncthing/Dolphin/{GC,StateSaves,GameSettings}

# Copy script:
cat > /data/media/0/sync_dolphin.sh << 'EOF'
#!/bin/sh
cp -r /data/media/0/Syncthing/Dolphin/GC/. \
      /data/media/0/Android/data/org.dolphinemu.dolphinemu/files/GC/
cp -r /data/media/0/Syncthing/Dolphin/StateSaves/. \
      /data/media/0/Android/data/org.dolphinemu.dolphinemu/files/StateSaves/
STAT_OUT=$(stat /data/media/0/Android/data/org.dolphinemu.dolphinemu)
UID=$(echo "$STAT_OUT" | grep "Uid:" | awk '{print $2}' | cut -d'/' -f1)
chown -R $UID:ext_data_rw /data/media/0/Android/data/org.dolphinemu.dolphinemu/files/
EOF
chmod +x /data/media/0/sync_dolphin.sh
Dolphin's Export Feature: As a manual fallback, Dolphin has Settings → Config → User Data → Export User Data. This exports everything to a folder of your choice. You can then sync that export folder with Syncthing. When moving to another device, use Import User Data.

Part 6: Linking All Devices Together (Mesh Sync)

By default, all devices sync through the Linux hub. But you can also make devices sync directly with each other — useful when both handhelds are on but the Linux PC is off.

To Enable Direct Device-to-Device Sync:

  1. Open the Syncthing Web GUI on Device A
  2. Click Add Remote Device
  3. Select Device B from the list of nearby devices
  4. In the Sharing tab, select the folders you want to share directly
  5. Click Save
  6. On Device B, accept the connection and folder shares

Now all three devices (Linux hub + two handhelds) form a mesh. If one is offline, the others still sync.

Conflict risk: With direct device-to-device sync, the same file could be modified on two devices simultaneously. Syncthing handles this by creating .sync-conflict files. Good habits prevent this: always save in-game and close the emulator on one device before starting to play on another.

Part 7: rclone — Backup Synced Folder to Google Drive

Syncthing syncs between devices, but it is not a backup. A corrupted save will sync everywhere. This is where rclone comes in — it backs up your Linux hub's synced folder to Google Drive on a schedule, giving you off-site redundancy.

Install rclone

# Ubuntu/Debian:
sudo apt install rclone

# Fedora:
sudo dnf install rclone

# Or the latest from the official install script:
curl https://rclone.org/install.sh | sudo bash

Configure Google Drive Remote

Create your own OAuth Client ID! rclone's shared client ID is being retired in 2026. You should create your own in the Google Cloud Console to avoid interruption. See the rclone docs for step-by-step instructions. 
rclone config

Follow the interactive prompts:

  1. n → New remote
  2. Name: gdrive
  3. Storage type: drive (or the number for Google Drive)
  4. client_id: Enter your own, or leave blank to use rclone's shared one (being retired)
  5. client_secret: Enter your own if applicable
  6. Scope: 1 (Full access — recommended for backup)
  7. root_folder_id: Leave blank (root of Drive)
  8. service_account_file: Leave blank
  9. Advanced config: n
  10. Use auto config: y — browser opens for OAuth
  11. Log in to Google and authorize rclone
  12. Shared Drive: n
  13. Keep this remote: y

Test the Connection

# List your Drive contents:
rclone lsd gdrive:

# Check quota:
rclone about gdrive:

Backup Strategy: rclone copy (Not sync!)

Use rclone copy, NOT rclone sync for backups!
sync makes the destination an exact mirror — files deleted locally get deleted on Drive too. copy only uploads new and changed files; it never deletes anything from Drive. This is the safer choice for backups.

Manual Backup Command

rclone copy ~/Sync/Emulators/ gdrive:EmulatorBackups/ \
    --progress \
    --create-empty-src-dirs \
    --verbose

This uploads everything from ~/Sync/Emulators/ into a folder called EmulatorBackups on Google Drive. Only new or modified files are transferred. Nothing is ever deleted from Drive.

Useful rclone Flags for This Setup

FlagPurpose
--progressShow transfer progress
--create-empty-src-dirsRecreate empty directories on Drive
--verbose / -vDetailed output for debugging
--dry-runSimulate — show what would happen without doing it
--max-age 24hOnly copy files modified in the last 24 hours
--transfers 4Number of parallel file transfers (default 4)
--bwlimit 1MLimit bandwidth to 1 MB/s (avoid saturating your connection)
--drive-chunk-size 64MOptimize upload chunk size for Google Drive
--exclude "*.state"Exclude save state files if you only want battery saves
--log-file /var/log/rclone-backup.logWrite output to a log file

Restoring from Google Drive

# Download everything back:
rclone copy gdrive:EmulatorBackups/ ~/Sync/Emulators/ --progress

# Or just restore a specific save:
rclone copy gdrive:EmulatorBackups/RetroArch/saves/ ~/Sync/Emulators/RetroArch/saves/ --progress

Part 8: Automating rclone with systemd Timer

Instead of running rclone manually, let's set up a systemd timer that backs up your sync folder to Google Drive every 6 hours.

Step 1: Create the Backup Script

sudo nano /usr/local/bin/backup-emulators-to-gdrive.sh

Paste the following:

#!/bin/bash
# Backup script: copies Syncthing emulator folder to Google Drive

SOURCE="$HOME/Sync/Emulators"
DEST="gdrive:EmulatorBackups"
LOG="/var/log/rclone-emulator-backup.log"
LOCK="/tmp/rclone-emulator-backup.lock"

# Prevent overlapping runs
if [ -e "$LOCK" ]; then
    PID=$(cat "$LOCK")
    if ps -p "$PID" > /dev/null 2>&1; then
        echo "$(date): Backup already running (PID $PID). Exiting." >> "$LOG"
        exit 0
    fi
fi
echo $$ > "$LOCK"

echo "$(date '+%Y-%m-%d %H:%M:%S'): Starting backup to Google Drive..." >> "$LOG"

/usr/bin/rclone copy "$SOURCE" "$DEST" \
    --progress \
    --create-empty-src-dirs \
    --transfers 4 \
    --exclude ".stfolder" \
    --exclude ".stversions" \
    --log-file "$LOG" \
    --log-level INFO

EXIT_CODE=$?

if [ $EXIT_CODE -eq 0 ]; then
    echo "$(date '+%Y-%m-%d %H:%M:%S'): Backup completed successfully." >> "$LOG"
else
    echo "$(date '+%Y-%m-%d %H:%M:%S'): Backup FAILED with exit code $EXIT_CODE." >> "$LOG"
fi

rm -f "$LOCK"
exit $EXIT_CODE
sudo chmod +x /usr/local/bin/backup-emulators-to-gdrive.sh

Step 2: Create the systemd Service

sudo nano /etc/systemd/system/rclone-emulator-backup.service
[Unit]
Description=RClone Backup — Emulator Saves to Google Drive
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
User=YOUR_USERNAME
ExecStart=/usr/local/bin/backup-emulators-to-gdrive.sh
StandardOutput=append:/var/log/rclone-emulator-backup.log
StandardError=append:/var/log/rclone-emulator-backup.log

[Install]
WantedBy=multi-user.target
Replace YOUR_USERNAME with your actual Linux username. The rclone config is stored per-user in ~/.config/rclone/, so the service must run as your user.

Step 3: Create the systemd Timer

sudo nano /etc/systemd/system/rclone-emulator-backup.timer
[Unit]
Description=RClone Backup Timer — Every 6 Hours
Requires=rclone-emulator-backup.service

[Timer]
OnCalendar=*-*-* 00:00:00
OnCalendar=*-*-* 06:00:00
OnCalendar=*-*-* 12:00:00
OnCalendar=*-*-* 18:00:00
Persistent=true
RandomizedDelaySec=300

[Install]
WantedBy=timers.target
Persistent=true means if the system was off during a scheduled backup, it runs immediately on boot. RandomizedDelaySec=300 adds up to 5 minutes of random delay so multiple timers don't all fire at once.

Step 4: Enable and Start

sudo systemctl daemon-reload
sudo systemctl enable rclone-emulator-backup.timer
sudo systemctl start rclone-emulator-backup.timer

# Verify:
sudo systemctl status rclone-emulator-backup.timer
systemctl list-timers | grep rclone

Step 5: Test It

# Run the service immediately to test:
sudo systemctl start rclone-emulator-backup.service

# Check the log:
sudo tail -f /var/log/rclone-emulator-backup.log

Part 9: Android Battery Optimization Tips

Syncthing on Android can drain battery because it constantly watches for file changes and maintains network connections. Here's how to minimize impact:

SettingRecommendationWhy
Android Battery Optimization Set to "Unrestricted" for Syncthing-Fork Prevents Android from killing Syncthing mid-sync, which causes more battery drain from restarts
Run Conditions → Run on mobile data OFF Only sync on Wi-Fi
Run Conditions → Run without network OFF Don't waste battery scanning when offline
Run Conditions → Time schedule ON (5 min cycle, 60 min interval) Syncs once per hour for 5 minutes instead of continuously
Syncthing Options → Global Discovery OFF Don't announce to global discovery servers
Syncthing Options → Enable Relaying OFF Don't use relay servers (only direct connections)
Folder → Watch for Changes OFF (use periodic rescan instead) Filesystem watching uses CPU. Set a rescan interval instead (e.g., 3600 seconds)
Manual force sync trick: After finishing a gaming session, open Syncthing-Fork → Status tab → FORCE START / IGNORE RUN CONDITIONS. This triggers an immediate sync. When done, tap FOLLOW RUN CONDITIONS to return to the battery-saving schedule. This gives you instant syncs when needed without constant battery drain.

Part 10: Troubleshooting & Best Practices

Best Practices

  1. Standardize your ROM library. Save files are named after ROM files. If Zelda.gba is named differently on different devices, saves won't sync. Use the exact same ROM set everywhere.
  2. Use the same RetroArch core on all devices. Save states are core-specific. An mGBA save state won't load on gPSP. Use consistent cores.
  3. Prefer in-game (SRAM) saves over save states for cross-device play. Save states (.state) are fragile and core-version-specific. Battery saves (.srm) are portable and reliable.
  4. Always close the emulator properly. RetroArch writes battery saves on content close. If you just power off, the save may not be written and Syncthing won't see it.
  5. One device at a time. Don't play the same game on two devices simultaneously. Finish, save, close the emulator, let it sync, then start on the other device.
  6. Enable file versioning everywhere. Simple File Versioning (keep 5-10 copies) is a lifesaver if a save corrupts and syncs everywhere.
  7. Periodically verify your Google Drive backup. Download a random save file and test it. Trust but verify!

Common Issues

ProblemLikely CauseSolution
Devices not connecting Firewall blocking ports Ensure TCP/UDP 22000 and UDP 21027 are open. Check both devices are on the same network or have relay enabled.
"Out of sync" or "failed items" File permissions on Android/data/ On locked devices, use the bridge-folder workaround with root scripts.
Save states not loading on another device Different RetroArch core or version Use the exact same core. Save states are NOT portable between different cores. Use battery saves instead.
Syncthing drains battery fast Continuous syncing and file watching Enable time-scheduled syncing (Section 9). Turn off file watcher, use periodic rescans.
Syncthing won't access Android/data/ Android scoped storage restrictions Use the Web GUI (not the app UI). On some devices (Anbernic), this still won't work — use the bridge-folder method.
Duplicate or conflict files Same file modified on two devices before sync Syncthing creates .sync-conflict files. Develop the habit of closing one device before starting another.
rclone "User rate limit exceeded" Google Drive API rate limiting Create your own OAuth Client ID. Add --tpslimit 10 to limit transactions per second.
rclone backup not running systemd timer not enabled or user mismatch Check systemctl list-timers | grep rclone. Ensure the service runs as the correct user (who has rclone config).

Syncthing Ignore Patterns — Advanced

Instead of creating many small shared folders, you can share one large folder and use ignore patterns to filter:

# Include only these (everything else ignored): !saves !states !cheats * # OR: Exclude specific items (everything else included): switch xbox xbox360 *.tmp

Checking Sync Status

# On Linux, check the Syncthing logs:
journalctl --user -u syncthing -f

# On Android, check the Web GUI at:
http://127.0.0.1:8384

# rclone backup logs:
sudo tail -f /var/log/rclone-emulator-backup.log
