Decision #3: Transcoding needs?

Direct Play (no transcoding) uses almost zero CPU. If all your clients support your media format — Apple TV 4K running Swiftfin or Android tablets running Findroid — you barely need any CPU at all. Both of these clients direct-play nearly all formats including 4K HDR.

Hardware Transcoding via Intel Quick Sync (integrated GPU) is the game-changer. A 6W N100 can transcode 4K HDR→1080p SDR with hardware tone mapping — something that would require a 17,000 PassMark CPU to do in software.

🎉 Jellyfin Advantage: Unlike Plex, Jellyfin offers completely free hardware transcoding. No paywall, no premium subscription required. Intel Quick Sync (QSV), VA-API, NVIDIA NVENC, and AMD AMF are all supported out of the box.

Factor this in when planning your 12TB usable target.

6. CPU Deep Dive: Intel Quick Sync & Jellyfin Transcoding

Why Intel (Not AMD) for Jellyfin Transcoding

Jellyfin supports Intel Quick Sync Video (QSV), VA-API (which AMD also supports), and NVIDIA NVENC for hardware transcoding. However, Intel's QSV implementation is the most mature, best-supported, and offers the best performance-per-watt. AMD's integrated graphics have limited/experimental tone mapping support in Jellyfin and lag significantly behind in encoding quality. For a Jellyfin-focused build, Intel is the clear choice.

Unlike Plex, Jellyfin has no artificial concurrent transcode limits on any GPU platform. Intel iGPUs and ARC dGPUs have no session cap — you're limited only by hardware performance.

Intel Quick Sync Generations Compared

12th Gen Intel and newer is the sweet spot for Jellyfin. Full AV1 decode, HEVC encode/decode, and hardware HDR→SDR tone mapping via both OpenCL and VPP (Video Post Processing).

Recommended HDDs for NAS / Jellyfin Use

  • Seagate IronWolf / IronWolf Pro — Designed for 24/7 NAS use, 7200 RPM, CMR. ~$30–$49/TB in Australia. IronWolf Pro 12TB is often cheaper than regular IronWolf at MSY/Umart — always check both.
  • Western Digital Red Plus — CMR only (avoid plain WD Red — SMR). Slightly quieter (5640 RPM), lower power than IronWolf. ~$28–$45/TB.
  • Seagate Exos — Enterprise-grade, often good value when on sale. Slightly louder but excellent reliability. 5-year warranty.
  • "Shucking" — Buying external USB drives and removing the internal HDD can save 30–50%. Common in Australia with WD Elements/Easystore. Caveat: warranty voided, may need 3.3V pin mod.
⚠️ Critical: CMR vs SMR: Never use SMR (Shingled Magnetic Recording) drives in any RAID, ZFS, or Unraid array. SMR drives suffer catastrophic write performance during RAID rebuilds — what should take hours can take days. All IronWolf and WD Red Plus drives are CMR. Avoid plain WD Red (often SMR) and most consumer desktop drives. Jellyfin itself doesn't care about CMR vs SMR, but your storage layer absolutely does.

10. Step-by-Step: Jellyfin Setup with Hardware Transcoding

This Guide Covers

A complete, production-ready Jellyfin setup on Ubuntu Server 24.04 LTS with Docker Compose, Intel Quick Sync hardware transcoding, HDR tone mapping, and all the fixes for common pitfalls. This has been tested extensively on N100 and i3-12100 hardware.

Prerequisites

  • Ubuntu Server 24.04 LTS (fresh install recommended)
  • Intel CPU with integrated GPU (N100, i3-12100, or similar 12th Gen+)
  • Docker and Docker Compose installed
  • Media files on local storage or mounted NAS share
  • Root or sudo access

Step 1: Install Docker & Prerequisites

# Update system
sudo apt update && sudo apt upgrade -y

# Install Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# Log out and back in for the group change to take effect

# Verify Docker
docker --version

# Install Docker Compose (standalone plugin)
sudo apt install docker-compose -y

Step 2: Install Intel GPU Drivers & Tools

# Install Intel media drivers and VA-API tools
sudo apt update
sudo apt install -y \
  intel-media-va-driver-non-free \
  vainfo \
  intel-gpu-tools \
  libdrm-intel1 \
  mesa-va-drivers

# Verify the GPU is detected
ls -la /dev/dri/
# Should show: card0, renderD128

# Check VA-API codecs
vainfo
# Should list VAProfileH264Main, VAProfileHEVCMain, etc.

# Verify Quick Sync engine
sudo intel_gpu_top
# Should show your GPU with Render/3D, Blitter, Video, VideoEnhance engines

⚠️ Critical: Install OpenCL for HDR Tone Mapping (N100 especially!)

Ubuntu 24.04's default intel-opencl-icd (23.x) works for N100. If you're on Ubuntu 22.04 or have issues, install from Intel's repo:

# Check current OpenCL version
apt policy intel-opencl-icd

# If version is below 23.x, install from Intel's GitHub releases:
# Visit https://github.com/intel/compute-runtime/releases
# Download the latest .deb packages and install:
# sudo dpkg -i intel-opencl-icd_*.deb intel-igc-core_*.deb etc.

# For Ubuntu 24.04, the default package works:
sudo apt install -y intel-opencl-icd

# Verify OpenCL is working with Jellyfin's ffmpeg (once Jellyfin is running)
# docker exec -it jellyfin /usr/lib/jellyfin-ffmpeg/ffmpeg \
#   -v verbose -init_hw_device vaapi=va:/dev/dri/renderD128 \
#   -init_hw_device opencl@va
🔴 The #1 N100 Jellyfin Issue: If tone mapping fails with Failed to get number of OpenCL platforms: -1001, your OpenCL runtime is too old. The N100's GPU ID (0x46D1) requires Intel compute-runtime 22.30+. Upgrade from Intel's GitHub releases.

Step 3: Create Jellyfin Directory Structure

# Create Jellyfin directories
sudo mkdir -p /opt/jellyfin/{config,cache}
sudo mkdir -p /media/{movies,tv,music}

# Set ownership to your user
sudo chown -R $USER:$USER /opt/jellyfin
sudo chown -R $USER:$USER /media

# Increase inotify watch limit for large media libraries
echo "fs.inotify.max_user_watches=524288" | sudo tee -a /etc/sysctl.d/99-jellyfin.conf
sudo sysctl -p /etc/sysctl.d/99-jellyfin.conf

Step 4: Get the Render Group ID

# Find the render group GID on your host
getent group render | cut -d: -f3
# Example output: 122 (Ubuntu) or 108 (Debian) or 989 (Proxmox LXC)

# Add your user to the render and video groups
sudo usermod -aG render,video $USER
# Log out and back in for this to take effect

Step 5: Create docker-compose.yml

cd /opt/jellyfin
nano docker-compose.yml

Paste the following (replace RENDER_GID with your actual render group ID and YOUR_SERVER_IP with your LAN IP):

services:
  jellyfin:
    image: jellyfin/jellyfin:latest
    container_name: jellyfin
    user: "1000:1000"  # Replace with your UID:GID (run 'id' to check)
    group_add:
      - "122"  # Replace with your render group GID (getent group render | cut -d: -f3)
    network_mode: 'host'
    volumes:
      - /opt/jellyfin/config:/config
      - /opt/jellyfin/cache:/cache
      - /media/movies:/media/movies:ro
      - /media/tv:/media/tv:ro
      - /media/music:/media/music:ro
    devices:
      - /dev/dri/renderD128:/dev/dri/renderD128
      - /dev/dri/card0:/dev/dri/card0
    environment:
      - JELLYFIN_PublishedServerUrl=http://192.168.1.100:8096  # Replace with your LAN IP
      - TZ=Australia/Sydney
    tmpfs:
      - /transcode  # RAM disk for transcode cache — saves SSD wear
    restart: unless-stopped
💡 tmpfs for transcodes: Mapping /transcode as tmpfs puts the transcode cache in RAM instead of your SSD. This saves SSD write cycles and speeds up transcoding. Jellyfin will use this automatically — just set the transcode path to /transcode in Dashboard → Playback. With 32GB RAM, allocate 8–16GB in the Jellyfin settings.

Step 7: Configure Hardware Acceleration in Jellyfin

  1. Open http://YOUR-SERVER-IP:8096 in a browser
  2. Complete the initial setup wizard (create admin user, add media libraries)
  3. Go to Dashboard → Playback → Transcoding
  4. Set Hardware acceleration: Intel Quick Sync (QSV)
  5. Check all supported codec boxes EXCEPT:

    • Uncheck Allow encoding in AV1 format (N100 cannot encode AV1; i3-12100 cannot either — only ARC GPUs can)

  6. ✅ Check Enable hardware decoding for: H264, HEVC, MPEG2, VC1, VP9, AV1
  7. ✅ Check Enable VPP Tone mapping (preferred for 12th Gen+; uses less power)
  8. ✅ Check Enable Tone mapping (OpenCL — enables Dolby Vision support; you can enable both)
  9. Set Transcoding thread count: Auto
  10. Under Transcoding path: enter /transcode (for the RAM disk)
  11. Click Save

11. Tips & Tricks for Jellyfin Perfection

🐧 OS-Level Optimizations

  • Use Ubuntu 24.04 LTS (not 22.04): Ships with kernel 6.8+, newer Intel GPU firmware, and a working OpenCL runtime for N100 out of the box. Saves hours of driver debugging.
  • Disable Ubuntu's automatic updates: sudo apt remove unattended-upgrades — you want to control when kernel/driver updates happen on a 24/7 server.
  • Enable kernel HWE stack: sudo apt install linux-generic-hwe-24.04 for the latest Intel GPU driver improvements.
  • Set CPU governor to powersave: echo "powersave" | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor — saves 2–4W at idle on desktop CPUs.

🎬 Transcoding Optimizations

  • Use the RAM disk for transcodes: Set transcode path to /transcode (tmpfs). This eliminates SSD wear from constant transcode writes. A 4K→1080p transcode can write 2–4GB of temporary segments per hour.
  • Prefer HEVC target encoding: Enable "Allow encoding in HEVC format" — HEVC provides ~40% smaller file size than H.264 at the same quality, saving bandwidth for remote streaming. The N100 and i3-12100 both encode HEVC in hardware just fine.
  • Enable VPP tone mapping first, OpenCL as backup: VPP uses less power. If you have Dolby Vision content, also enable OpenCL tone mapping — Jellyfin will pick the right method per file.
  • Set a reasonable CRF: Under Dashboard → Playback, set "H264 encoding CRF" to 23 (default) and "HEVC encoding CRF" to 25. Lower = better quality but more bandwidth. These defaults are good for most users.
  • Throttle transcode ahead: Set "Throttle transcodes" to on — Jellyfin stops transcoding when the buffer is full, then resumes as needed. Saves power during playback.

📚 Library & Metadata Tips

  • Organize files strictly: /media/movies/Movie Name (Year)/Movie Name (Year).mkv and /media/tv/Show Name/Season 01/Show Name - S01E01.mkv. Jellyfin's auto-detection depends on this.
  • Enable Trickplay images: Dashboard → Playback → Trickplay. Generates thumbnail previews when scrubbing. Costs some storage but massively improves UX.
  • Use the Jellyfin Intro Skipper plugin: Auto-detects and skips TV show intros. Works locally (no cloud dependency).
  • For anime: Install the AniDB and AniList metadata plugins. The default TMDb scraper struggles with anime naming.
  • Large libraries (5,000+ files): Initial scan may take 30–60 minutes. Be patient. Metadata is fetched from TMDb, TVDb, and MusicBrainz — internet speed matters.

📱 Client Setup: Android Tablets & Apple TV

This build is designed for two specific client types. Here's everything you need to know to set each one up for the best experience.

Android Tablets — Findroid (Recommended)

  • App: Findroid — third-party Jellyfin client built from the ground up for Android. Free on Google Play and F-Droid.
  • Key features: Native player with excellent codec support, offline downloads, MPV-based playback for wide format compatibility, gesture controls, and a modern Material You interface.
  • Alternative: Official Jellyfin Android app — also free. Uses ExoPlayer or web player. Good fallback if Findroid has issues with specific files.
  • Direct play capability: Both Findroid and the official app can direct-play H.264, HEVC, and many other formats natively. For 4K HDR, Findroid handles it better thanks to its MPV backend.
  • Offline downloads: Both apps support downloading media for offline playback — great for travel or kids' tablets.
  • Setup: Install from Google Play → enter server URL (e.g., http://192.168.1.100:8096) → log in. That's it. No configuration needed on the server side.

Apple TV — Swiftfin

  • App: Swiftfin — native Jellyfin client for tvOS. Free on the App Store. Built by the Jellyfin project.
  • Key features: Native SwiftUI interface, direct plays nearly everything including 4K HDR (HDR10, Dolby Vision Profile 5 & 8), and uses the native tvOS video player for the best performance.
  • Hardware required: Apple TV 4K (1st gen or newer). The older Apple TV HD works but lacks 4K and HDR support. Apple TV 4K (3rd gen, 2022) with the A15 Bionic chip is ideal — it has the most powerful decoder and supports HDR10+ and Dolby Vision.
  • Direct play advantage: Apple TV 4K direct-plays nearly all modern media formats. This means zero transcoding on the server when watching from the Apple TV — your Jellyfin server can be practically asleep. H.264, HEVC, HEVC 10-bit (HDR), and Dolby Vision all play natively.
  • Audio note: Apple TV does not passthrough lossless audio formats (TrueHD, DTS-HD MA). These will be transcoded to multichannel PCM or AAC on the server. This uses minimal CPU and is handled seamlessly. For most users with TV speakers or soundbars, this is a non-issue.
  • Setup: Install Swiftfin from the App Store → enter server URL → log in. All configuration happens on-device — no server-side changes needed.

🌐 Remote Access Options

  • Tailscale (recommended): Free for personal use. Install on server and all client devices (available on Android and Apple TV via TestFlight/sideloading). Creates a private mesh VPN — no port forwarding needed, works through CGNAT. curl -fsSL https://tailscale.com/install.sh | sh
  • Cloudflare Tunnel: Free. Exposes Jellyfin via Cloudflare's network with HTTPS. No port forwarding. Requires a domain name (can use a free .tk or cheap .com). Works with both Android and Apple TV clients.
  • WireGuard VPN: Self-hosted. More complex but fully self-contained. Use wg-easy Docker container for simple setup. WireGuard clients available for Android and can be configured on Apple TV via router-level VPN.
  • Reverse proxy (Nginx + Let's Encrypt): If you have a public IP. Use Nginx Proxy Manager for an easy web UI.
  • Avoid: Direct port forwarding without HTTPS. Use at minimum a reverse proxy with SSL.

13. What You Might Have Missed

🔌 Power Supply Efficiency at Low Loads

Most ATX PSUs are designed for gaming PCs and operate poorly at the very low loads a home server typically draws (10–50W). A 750W PSU at 3% load may only be 50–60% efficient — meaning your system draws 30W at the wall but only 15–18W reaches the components. Solutions:

  • Use a PicoPSU (DC-DC) with an external power brick — ~90% efficient at low loads
  • Choose an 80+ Platinum or Titanium rated PSU (tested down to 10% load)
  • The be quiet! Pure Power 12 M series specifies efficiency down to 2% load
  • Size your PSU appropriately — 450W is plenty for a server without a discrete GPU

🌡️ HDD Cooling Matters

6 drives packed tightly in a Node 304 can hit 45–50°C under sustained load — shortening drive lifespan. Ensure good airflow: intake fans in front, exhaust in rear. Keep drives below 40°C for longevity. The Node 304's included fans + a rear exhaust fan does this well. For the N100 mini PC with external enclosures, ensure the enclosure has active cooling (a fan).

📡 Remote Access & Security

Don't port-forward Jellyfin directly. Use Tailscale (free for personal use) or WireGuard VPN for secure remote access. If you must expose Jellyfin publicly, use a reverse proxy (Nginx Proxy Manager + Let's Encrypt) and enable 2FA on your Jellyfin accounts. Jellyfin supports TOTP 2FA natively.

🔋 UPS (Uninterruptible Power Supply)

For a server running 24/7, a UPS protects against power surges and gives clean shutdown time. A basic 650VA UPS costs ~$100–$150 AUD. Connect via USB and configure automatic shutdown in Unraid/TrueNAS when battery is low. For Ubuntu/Debian, use NUT (Network UPS Tools) — free and well-supported.

🔄 Backup Strategy

RAID/parity is not backup. Follow the 3-2-1 rule: 3 copies, 2 different media, 1 offsite. For media that can be re-downloaded, this may be overkill — but for personal documents, photos, and your Jellyfin config directory (watch history, user accounts), use cloud backup (Backblaze B2, ~$6/TB/month) or an external drive rotated offsite.

Critical: Back up /opt/jellyfin/config regularly. If you lose this, you lose all watch history, user accounts, library customizations, and metadata. The media files can be re-scanned, but the config is irreplaceable.
